# Momentum to Raindance

Three .NET 8 Frends tasks for Momentum invoice export with permanent PostgreSQL invoice tracking. Uses Npgsql 8.0.9. Version 2.x requires a database-backed workflow; upgrading is not a drop-in replacement for checkpoint-only conversion.

- **Fetch Ledger Note Accountings** returns prettified GraphQL JSON as a string and the unchanged input `LastLocalId`. Optional processing can run after fetching.
- **Convert GraphQL Result** takes that JSON, the same checkpoint, and required database settings. It validates and durably reserves previously unseen `(SourceSystem, ledgerNote.id)` identities **before returning bytes**. Result fields include `ResultFile`, `Filename`, `NodeCount`, `SkippedInvoiceCount`, `DeliveryId`, `ContentSha256`, and the proposed `LastLocalId`.
- **Confirm Invoice Delivery** records evidence after the external file writer succeeds. Persist its returned checkpoint afterward. Confirmation is idempotent with identical source, fingerprint and evidence; the writer must not be retried automatically.

Conversion `ResultFile` is still `byte[]`, already ISO-8859-1/Latin-1 encoded with fixed-width spaces and CRLF. `Filename` is a string in `300K24_yyyyMMdd_HHmmss.txt` format. Pass these to the existing file writer's File and Byte content inputs respectively, using RAW mode and overwrite off. Do not re-encode. On `NodeCount == 0`, skip the writer and confirmation: output bytes, filename, delivery ID and hash are empty. Verified historical/delivered duplicates can advance the cursor without emitting a file; entirely no-op input preserves it.

An unresolved reservation blocks the whole source and never expires or automatically releases. Confirmed/historical identities are never re-exported through this workflow. This provides at-most-once admission, **not a distributed exactly-once delivery guarantee**: manually copied or cached output and writer retries remain unsafe. A recorded delivery means file delivery, not Raindance import.

Before production, run the separate offline migrations, reconcile and seed previously delivered invoice IDs, register/activate a permanent source, and configure your existing database login on Convert and Confirm. The same login can perform setup and runtime work; a separate restricted login is optional. Follow the [numbered first-time setup](../database/README.md); no user creation is required. There are no Frends-time migrations or untracked production mode. Keep identity history permanently, with backups and restore reconciliation. The local CLI is diagnostic preview only and its output must not be delivered.

API and database settings accept JSON, manual configuration, or canonical **HcpVault**, currently backed by Infisical. Use separate secrets; production connections require verified TLS. All tasks support cancellation and fail by throwing, without returning partial output.

Read the [setup and API documentation](https://github.com/Hoglandets-IT/Frends.HIT.MomentumToRaindance#readme), [database administration](https://github.com/Hoglandets-IT/Frends.HIT.MomentumToRaindance/blob/main/database/README.md), [field mapping](https://github.com/Hoglandets-IT/Frends.HIT.MomentumToRaindance/blob/main/docs/raindance-format.md), and [production runbook](https://github.com/Hoglandets-IT/Frends.HIT.MomentumToRaindance/blob/main/docs/operations.md).
